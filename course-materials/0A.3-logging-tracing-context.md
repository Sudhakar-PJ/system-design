# Level 0A.3 — Logging, Tracing & Context Propagation

## 1. Structured JSON Logging vs Text Logs

In production backend engineering, unstructured string logs (like `console.log("User logged in: " + userId)`) are anti-patterns. Log aggregation platforms (Elasticsearch/Kibana, Datadog, Loki) cannot query, index, or alert on raw string streams efficiently.

**Structured JSON Logging** formats every log record as a schema-compliant JSON object:

```json
{
  "level": 30,
  "time": 1726723200000,
  "pid": 12345,
  "hostname": "api-service-7f89b-x2k9l",
  "requestId": "req_9f8a2b3c4d5e",
  "traceId": "0af7651916cd43dd8448eb211c80319c",
  "spanId": "b7ad6b7169203331",
  "msg": "User profile fetched successfully",
  "userId": "usr_m15ye3n",
  "durationMs": 14.2
}
```

## 2. Distributed Tracing Mental Model & W3C `traceparent`

When a request flows through microservices (e.g. `Client → API Gateway → Auth Service → Order Service → Database`), tracking a single request across asynchronous boundaries requires **Distributed Tracing**.

```
[ HTTP Request ] (Header: traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01)
       │
       ▼
┌─────────────────────────────────────────────────────────────┐
│ Root Span (API Gateway / Express Server)                    │
│ Trace ID: 4bf92f3577b34da6a3ce929d0e0e4736                   │
│ Parent Span ID: 00f067aa0ba902b7                            │
└──────────────────────────────┬──────────────────────────────┘
                               │
               ┌───────────────┴───────────────┐
               ▼                               ▼
  ┌─────────────────────────┐     ┌─────────────────────────┐
  │ Child Span (UserService)│     │ Child Span (DB Query)   │
  │ Span ID: a1b2c3d4e5f67890│     │ Span ID: f9e8d7c6b5a43210│
  └─────────────────────────┘     └─────────────────────────┘
```

### W3C `traceparent` Header Specification:
Format: `version-trace_id-parent_id-trace_flags`
Example: `00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
- `version`: `00` (Current W3C spec version).
- `trace_id`: 16-byte (32 hex character) unique trace identifier.
- `parent_id`: 8-byte (16 hex character) unique span identifier.
- `trace_flags`: 8-bit field (e.g. `01` means sampled for tracing).

## 3. `AsyncLocalStorage` for Request-Scoped Context Propagation

Passing `requestId`, `traceId`, or `userId` manually through every function parameter across controllers, services, and repositories (`parameter drilling`) pollutes business logic.

Node.js `AsyncLocalStorage` provides thread-local-like context propagation across asynchronous call chains:

```typescript
import { AsyncLocalStorage } from 'async_hooks';

export interface RequestContext {
  requestId: string;
  traceId: string;
  userId?: string;
}

export const contextStorage = new AsyncLocalStorage<RequestContext>();

// Inside middleware:
app.use((req, res, next) => {
  const context: RequestContext = {
    requestId: (req.headers['x-request-id'] as string) || `req_${randomUUID()}`,
    traceId: parseTraceId(req.headers['traceparent'] as string) || randomUUID(),
  };

  contextStorage.run(context, () => {
    next(); // All downstream async code has access to contextStorage.getStore()!
  });
});
```

## 4. Pino High-Performance Logger & PII Redaction

**Pino** is the fastest JSON logger for Node.js. It offloads JSON stringification and uses asynchronous stream buffers to avoid blocking the single-threaded event loop.

### PII Redaction Rules:
Security standards (GDPR, PCI-DSS, HIPAA) forbid logging Sensitive Personal Data (PII). Pino supports automatic path-based redaction:

```typescript
import pino from 'pino';

export const logger = pino({
  redact: {
    paths: [
      'req.headers.authorization',
      'req.headers.cookie',
      'password',
      'creditCard',
      'ssn',
      'email'
    ],
    censor: '[REDACTED]',
  },
});
```
